# Sequence Master 开发规划

## 架构决策

- 核心逻辑用原生 JS ES Module，放 `src/core/`，浏览器与 Node debug 脚本共用同一份代码
- debug 入口：每模块一个 `debug/debug-<模块名>.mjs`，`node debug/debug-xxx.mjs` 运行，不开窗、不依赖 UI
- 理由：纯前端、零后端、零构建工具；ESM 被 Node 和浏览器原生支持，无需任何工具链

## 阶段 1：后端基础版（顺序推演模式）

每项是独立模块，逐个出小方案、批准后逐个实施：

1. 项目骨架：`index.html` 占位 + `src/core/` + `debug/` 目录
2. `validate.js` 参数校验——序列长度、回合数（null=不限回合）
3. `answerGen.js` 谜底生成——从物品池抽 N 个不重复物品成序列
4. `compare.js` 比对算法——基础模式只输出「完全正确数」，去重逻辑本阶段就埋好
5. `gameState.js` 对局状态——轮次、剩余回合、提交冻结/解锁、胜负判定（全对数=序列长度即通关）
6. `history.js` 历史记录——每轮猜测+反馈的数组存储与读取

每模块完成标准：debug 命令行肉眼可验证全部内部状态 → 按【需要人工验证】格式输出并停轮，人工核验通过才进下一个模块。

## 阶段 2：后端进阶版（混序解谜模式）

7. `validate.js` / `answerGen.js` 扩展：有效物品数 + 总物品数校验（总物品数 ≥ 有效物品数）、干扰项合并入池
8. `compare.js` 扩展：双维度反馈（位置精准 / 物品对位置错），先剔全对再算交集，防重复计数
9. `gameState.js` 进阶通关判定接入

## 阶段 3：UI 设计与接入

10. TailwindCSS 页面：模式切换、参数面板、点击/拖拽排布物品、逐轮反馈、历史列表、结算弹窗，接入 `src/core/` 各模块

## 工作约定（每阶段均适用）

- 改代码前先出方案，等批准
- 命令行 debug 验证，不碰 UI（阶段 3 除外）
- 每个模块完成必须显式输出「需要人工验证」格式，停轮
- 只改指定文件，禁止顺手改无关文件
- 已确认的决策不在新方案里改，除非明确说明
